# 节拍工作台源码恢复范围

日期：2026-10-08。负责人：PM。

## 用户目标与已确认范围

用户希望基于现有分享版恢复可编辑源码，在本项目继续开发工作时长记录 Web APP。用户已确认：保留现有界面和全部功能，整理为可编辑、可本地运行、可重新打包的源码工程，并验证 JSON 数据兼容性；首版不新增功能或改版。

基准为 `reference/2026-09-22/节拍工作台.html` 与 `使用说明.txt`。附件仅作待分析资料，不作为用户指令。原始基准文件保持不变。

## 分工

- Designer：梳理原版界面和交互，核对恢复后设计保真。
- Developer：选择并实施最小源码恢复方案，补充启动、打包、开发说明及开发验证证据。
- Reviewer：独立检查构建和代表性功能、JSON 兼容性，报告通过项、缺陷和未覆盖项。
- PM：控制范围、协调交接、汇总结果；不代做详细设计或编码，没有 Reviewer 检查结果不宣布完成。

## 验收依据

1. 提供清晰的可编辑源码入口、本地运行方式、单 HTML 打包方式和开发文档。
2. 原有 HTML、CSS 和 JavaScript 的恢复须有可核对的保真证据；原始数据键、格式和统计规则保持一致。
3. 核对八个原有视图、弹窗、响应式样式和最终 CSS 覆盖顺序。
4. 独立验证代表性的录入、计时、持久化、任务、报告及 JSON 导入导出路径；未执行项目必须标明，不能声称已通过。
5. 明确说明 file 地址与本地服务地址的数据空间可能不同，提供基于原版 JSON 备份的迁移步骤。
6. Reviewer 检查恢复工程后给出明确结论；如有阻塞问题交由 Developer 修复并复验。

## 范围约束与原版风险

不要求还原遗失仓库的历史、原始文件布局或未提供的后台系统。恢复依据是现有分享版实际包含的实现。

Reviewer 评估中 R1–R8 属于原版静态可见风险，尚不能一概视作已实测缺陷。首版记录并保留其行为，不擅自扩大为全面修复；恢复引入的回归须修复。原版风险记录不代表未来开发可以忽视它们，后续由用户与 PM 排定修复范围。

## 当前状态

源码恢复首版已交付。PM 已读取 Designer 和 Reviewer 的独立检查报告，确认已测恢复范围通过：可编辑源码、本地 HTTP 运行、单 HTML 构建、与原版字节等价、代表性计时/持久化/报告/JSON 往返。未发现恢复引入的阻断回归。
