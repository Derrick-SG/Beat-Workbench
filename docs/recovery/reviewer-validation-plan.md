## 就绪后执行顺序

1. 固定交付版本：记录文件清单、源码/构建入口、运行和打包命令、产物路径、原版 SHA256；执行前确认产品代码处于交付状态。
2. 静态等价：独立比较原版与拆分后 HTML/CSS/JS，明确只允许的资源引用、打包包装和路径变化；对照存储键、JSON 结构、事件绑定和报告生成逻辑。记录比较算法与差异，不把哈希/文本等价等同浏览器功能通过。
3. 运行和构建：按交付文档从源码启动、执行单 HTML 打包；确认错误输出、退出状态、产物是否自包含，再对产物做语法与引用检查。不能仅以产物已存在判定可构建。
4. 浏览器实测：分别检查本地源码入口与单 HTML 分享入口，记录浏览器版本、URL/协议、控制台可见错误和代表性界面证据。file 入口若工具无法访问，明确列未覆盖，不用 HTTP 入口替代其结论。
5. 回归对照：同一浏览器环境、同一隔离样本，在原版与恢复版执行对应路径。原版风险与新增差异分开报告；不改真实用户数据、不调用真实外部发送操作。

## 证据分层与完成条件
