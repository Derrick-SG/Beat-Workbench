# Beat-Workbench 产品需求文档

更新日期：2026-10-16（Asia/Shanghai）

版本：V1.1.0 候选发布

负责人：PM；设计：Designer；实现：Developer；独立验收：Reviewer。

## 1. 目标与状态

为个人工作提供快速记录、项目任务、心流及会议计时、周期复盘，并让用户明确掌握数据位置和恢复方式。

本版重点是用户资料、可选本地目录、可靠保存和异常心流结算。此前稳定交付为V1.0.0；本次发布V1.1.0候选包，不以专项通过代替全部平台验收。该文档记录已确认需求与当前实现，不新增开发范围。

## 2. 用户与使用方式

- 面向主动记录工作的个人用户；本机可建立多个独立用户档案。
- 固定本机入口为 `http://127.0.0.1:4173/#work-entry`。不同端口、浏览器和浏览器配置的数据空间独立。
- 本机用户档案不是云账号；名字相同不代表数据源相同。本版没有云登录、后台同步或团队权限体系。
- 完整源码通过Node本机服务运行；分享ZIP提供单HTML和说明。启动器、自启动配置属于完整源码，不包含在单HTML分享ZIP内。

## 3. 功能需求

| 编号 | 要求 | 行为与边界 |
|---|---|---|
| F01 | 工作记录和复盘 | 保留快速录入、任务、会议、周期报告和原有导出功能；不扩大为新的团队管理系统 |
| F02 | 编辑当前用户 | 修改名字/圆形头像保持稳定用户ID、用户数量及记录任务归属；新建和导入独立用户使用不同入口 |
| F03 | 选择默认目录 | 支持的浏览器保存目录句柄；同源同浏览器且权限有效时重开读取，失权要求重新连接；不承诺所有浏览器任意路径自动读取 |
| F04 | 更换存储目录 | 空目标可迁移完整工作区，关闭写入、回读和来源设置成功后才切换；保留原文件；已有数据明确使用目标或另选，不自动合并覆盖 |
| F05 | 保存故障保护 | 读取来源设置异常不静默加载旧浏览器副本；写失败显示明确错误、保留待保存副本，允许重试/导出；未完成保存有退出提示 |
| F06 | 长时保存可恢复 | 保存请求默认15秒期限、队列上限8，超时保留救援入口；禁止同仓库并发，迟到结果须核对，超时不等于取消底层IO |
| F07 | 心流可靠启动 | 选项目并点击开始后立即保存稳定会话ID、用户/工作区、项目和真实开始时间，保存成功才正式激活；失败不假启动并可重试 |
| F08 | 正常心流完成 | 支持超过24小时，按实际工作分段结算，成功保存后清会话；同会话不重复记账 |
| F09 | 异常心流结束确认 | 重开识别未结算心流，强制填写实际结束日期时间；按开始至人工结束完整跨度结算，含退出间隔，提示并预览；成功才解锁 |
| F10 | 本机便捷启动 | 固定4173回环地址；一键启动复用本项目服务，冲突不杀其他程序不换端口；可启停当前用户登录自动启动 |

## 4. 用户资料与数据模型

名字去除两端空格，长度1–30字符，不与另一用户重名。头像支持JPEG/PNG/WebP，输入不超过5MB、1600万像素，处理为256×256且不超过200KB。圆形显示是本项目设计，不声称Apple统一尺寸。

工作区包含全部用户、记录、任务及未结算会话。目录主文件为 `beat-workbench.workspace.json`，上一份快照为 `beat-workbench.previous.json`；显式损坏恢复保留原件，不静默初始化。单用户JSON备份为v4，兼容旧v3/记录数组；单用户备份不等同完整工作区或未结算会话备份。

不将真实工作记录、头像、目录文件、凭据及本机运行日志加入GitHub或分享包。源码历史备份不能代替个人工作数据备份。网盘管理的文件夹不意味着本版具备跨设备强一致同步。

## 5. 心流生命周期与计时规则

### 5.1 开始

选择项目并点击开始 → 显示保存起点 → 当前来源成功保存 → 显示已开始并计时。不能依赖关闭页面时才保存起点。浏览器和目录模式使用相同会话逻辑；临时会话明确提示不能保证关闭后恢复。

### 5.2 正常完成

写入实际工作分段、工作记录和结算标记，成功后清理运行状态和未结算会话。跨日、跨年和超过24小时按分段分配周期统计；不伪造最短一分钟。会议与任务计时不改用异常心流的全跨度口径。

### 5.3 异常重开

恢复弹窗显示当前项目、用户、完整开始时间和最后成功检查点。结束输入留空，不默认当前时间，不替用户推断实际结束时间。

- 必须填写完整结束日期和时间，支持秒级精度；严格晚于开始且不晚于当前时刻。
- 空值、零时长、早于开始、未来或无效时间拒绝提交，保留输入并明确提示。
- 人工确认按开始到结束完整跨度计工时，包含软件退出后至所填结束时间的间隔；这与此前“恢复仅计检查点时间”不同。
- 无放弃、稍后、Esc或背景跳过；仍有未结算会话时，意外关闭会重新出现确认层。
- 写失败保留会话及已提交的结束时间，可重试或导出待保存副本；导出不代表结算成功，也不解除确认。
- 多条会话依次处理，每条显示自身项目/起点并清空上一条输入；弹窗再次出现可能是下一条，不自动判定为保存失败。
- 重复点击、失败重试及不确定回执后重开保持幂等，每个会话仅一条记录。

### 5.4 保存挂起

保存超时不丢弃候选，不因开放界面而允许并发覆盖。数据管理、暂离心流、可见保存状态和导出入口保持可达；重试必须核对迟到结果。浏览器冻结、强杀、断电和权限失效不承诺无条件写入成功，可靠起点以启动时实际成功保存为前提。

## 6. 验收证据与限制

| 范围 | 当前证据 | 判定 |
|---|---|---|
| 自动与生产函数集成 | Reviewer独立65/65；包含超时队列、迟到写、启动/结算、日期校验、重试和分段统计 | 专项通过 |
| 浏览器真实操作 | 隔离页UI开始、刷新恢复、空/零拒绝、导出不解锁、Esc保持、双击确认及重开每会话一条 | 专项通过 |
| 目录持久化 | 生产仓库/控制器与真实临时磁盘，文件句柄适配；开始和25小时人工结算回读、跨年归属、幂等 | 集成通过，不代表原生授权完整实测 |
| Designer | 最终静态核对交互及错误状态符合 | 静态通过，不等同全部视觉实测 |
| 所有设备和环境 | 原生目录权限全生命周期、跨平台、真实重新登录、连续49小时及强杀/断电未全面验证 | 限制保留 |
| 历史个人数据 | 未确认原事件唯一原因或缺失记录完整性 | 不宣称恢复 |

验收报告：[心流独立验证](planning/20261016-flow-recovery-reviewer-verification.md)、[开发交接](planning/20261016-flow-developer-handoff.md)、[Designer核对](planning/20261016-flow-designer-verification.md)。此前资料与目录专项见20261014相关记录，不扩张既有证据范围。

## 7. 发布与协作规则

PM负责范围、PRD、日志与累计memory；Designer负责设计；Developer实现和构建；Reviewer独立验证。没有Reviewer结果不宣布完成。

分享包命名 `YYYYMMDD_Beat-Workbench_V主.次.修订.zip`，版本memory保存于 `docs/memory/`。本次包为 `20261016_Beat-Workbench_V1.1.0.zip`，历史包保留。每次迭代上传同时更新包、README入口、CHANGELOG和memory，Reviewer核对后同提交上传，推送后核对远端。未完成整版验收保留候选标记，不因文档提交升号。

本次不包含云同步、原生桌面程序、团队计费/审批、自动活动采集，也不把未经审核的市场分析初稿作为需求依据。
