# Beat-Workbench 产品需求文档

更新日期：2026-10-19（Asia/Shanghai）

版本：V1.1.1

负责人：PM；设计：Designer；实现：Developer；独立验收：Reviewer。

## 1. 目标与状态

为个人工作提供快速记录、项目任务、心流及会议计时、周期复盘，并让用户明确掌握数据位置和恢复方式。

本版重点是用户资料、可选本地目录、可靠保存和异常心流结算。此前稳定交付为V1.0.0；本次发布V1.1.0分享包，不以专项通过代替全部平台验收。该文档记录已确认需求与当前实现，不新增开发范围。

## 2. 用户与使用方式

- 面向主动记录工作的个人用户；本机可建立多个独立用户档案。
- 固定本机入口为 `http://127.0.0.1:4173/#work-entry`。不同端口、浏览器和浏览器配置的数据空间独立。
- 本机用户档案不是云账号；名字相同不代表数据源相同。本版没有云登录、后台同步或团队权限体系。
- 完整源码通过Node本机服务运行；分享ZIP提供单HTML和说明。启动器、自启动配置属于完整源码，不包含在单HTML分享ZIP内。

## 3. 功能需求

| 编号 | 要求 | 行为与边界 |
|---|---|---|
| F01 | 工作记录和复盘 | 保留快速录入、任务、会议、周期报告和原有导出功能；不扩大为新的团队管理系统 |
| F02 | 编辑当前用户 | 修改名字/圆形头像保持稳定用户ID、用户数量及记录任务归属；新建和导入独立用户使用不同入口 |
| F03 | 选择默认目录 | 支持的浏览器保存目录句柄；同源同浏览器且权限有效时重开读取，失权要求重新连接；不承诺所有浏览器任意路径自动读取 |
| F04 | 更换存储目录 | 空目标可迁移完整工作区，关闭写入、回读和来源设置成功后才切换；保留原文件；已有数据明确使用目标或另选，不自动合并覆盖 |
| F05 | 保存故障保护 | 读取来源设置异常不静默加载旧浏览器副本；写失败显示明确错误、保留待保存副本，允许重试/导出；未完成保存有退出提示 |
| F06 | 长时保存可恢复 | 保存请求默认15秒期限、队列上限8，超时保留救援入口；禁止同仓库并发，迟到结果须核对，超时不等于取消底层IO |
| F07 | 心流可靠启动 | 顶部心流入口不以项目为前置，点击即保存起点并开始；立即保存稳定会话ID、用户/工作区、项目和真实开始时间，保存成功才正式激活；失败不假启动并可重试 |
| F08 | 正常心流完成 | 支持超过24小时，按实际工作分段结算，成功保存后清会话；同会话不重复记账 |
| F09 | 异常心流自动结束 | 重开自动按最后成功检查点及真实已存分段结算，无人工结束确认；不计关闭间隔，失败保留重试/导出 |
| F10 | 本机便捷启动 | 固定4173回环地址；一键启动复用本项目服务，冲突不杀其他程序不换端口；可启停当前用户登录自动启动 |

### 3.1 本轮交互精简

用户已确认：一次明确选择后直接执行常规可逆操作，合并重复确认，不自动丢弃数据或推断心流实际结束时间。

| 操作目标 | 应用内步数变化 | 最终行为 |
|---|---|---|
| 心流开始/完成 | 顶部点击即开始；完成1次 | 空项目也直接启动；运行中可补选项目且起点不变，重复进入不新建；同位置主按钮随状态变化 |
| 保存资料并退出 | 2→1 | 仅显式保存成功关闭，失败保留输入，关闭后给可见反馈 |
| 空目录迁移 | 2→1 | 具名迁移入口及邻接说明，选空目标后直接复制并验证；原源保留 |
| 干净重新加载 | 2→1 | 无未保存内容直接执行；有未保存内容最多一层影响摘要，取消保留 |
| 浏览器恢复与旧副本 | 重复确认整合一层 | 显示来源和将放弃内容，明确动作后执行，不静默合并覆盖 |
| 多条异常心流 | 每条仍一次人工输入与保存 | 显示X/N，成功自动下一条并清空旧输入，不增加成功确认 |

步数不计填字段、进入页面和系统权限。次要恢复操作默认收起，故障按状态展开；用户备份与全工作台待保存副本分别标明范围。必要的未保存丢弃、不可逆删除、损坏写回知情保留，不新增自动保存资料或撤销系统。

## 4. 用户资料与数据模型

名字去除两端空格，长度1–30字符，不与另一用户重名。头像支持JPEG/PNG/WebP，输入不超过5MB、1600万像素，处理为256×256且不超过200KB。圆形显示是本项目设计，不声称Apple统一尺寸。

工作区包含全部用户、记录、任务及未结算会话。目录主文件为 `beat-workbench.workspace.json`，上一份快照为 `beat-workbench.previous.json`；显式损坏恢复保留原件，不静默初始化。单用户JSON备份为v4，兼容旧v3/记录数组；单用户备份不等同完整工作区或未结算会话备份。

不将真实工作记录、头像、目录文件、凭据及本机运行日志加入GitHub或分享包。源码历史备份不能代替个人工作数据备份。网盘管理的文件夹不意味着本版具备跨设备强一致同步。

## 5. 心流生命周期与计时规则

### 5.1 开始

点击顶部心流入口即捕获真实起点并保存，不要求先选项目或另点开始 → 当前来源成功保存 → 显示已开始并计时。运行中可补选或修改所属项目，持久化到同一会话，保留最初ID与开始时间。未选项目正常完成时就地补选，保留计时；异常恢复时自动以最后成功检查点结算，空项目使用系统未分类占位。运行中再次点击入口只展示当前心流，不建立重复会话。不能依赖关闭页面时才保存起点。浏览器和目录模式使用相同会话逻辑；临时会话明确提示不能保证关闭后恢复。

### 5.2 正常完成

写入实际工作分段、工作记录和结算标记，成功后清理运行状态和未结算会话。跨日、跨年和超过24小时按分段分配周期统计；不伪造最短一分钟。会议与任务计时不改用异常心流的全跨度口径。

### 5.3 异常重开：最后成功检查点自动结束

2026-10-19用户明确更改本规则，覆盖此前强制人工实际结束时间与包含关闭间隔的口径。重开自动读取已成功持久化的心流快照，以最后成功检查点结束；不要求结束日期输入，也不将关闭后时间计入。存在持久化分段时只结算真实已存分段，不把起点至检查点整个跨度当作工作。

- 成功写入结算记录后才清理原会话，保持原用户归属与会话ID幂等，不重复记账。
- 当前页面仍在运行的会话不进入自动恢复结算。
- 空项目不阻塞自动结束，使用明确未分类占位，后续可编辑同一条记录补项目。
- 仅起点无正时长，不伪造最短分钟；保留可追溯零时长结束凭据，不阻塞下次开始。
- 无法验证的旧会话保留并显示恢复错误，不猜测结束时间。
- 保存失败保留会话及待保存副本，显示重试、重新授权和导出；不再要求输入结束时间。未成功的检查点不可当作已落盘成功。
- 不承诺关闭事件中的异步写入成功；实际结算依赖已成功保存的快照。

本规则已专项验收通过：PM与Reviewer各完整84/84；Reviewer实际重开自动结算、无确认层、重复重开单条，以及零时长凭据浏览器/临时目录重开保留通过。此前人工结束测试仅作历史证据。详见当日checkpoint-auto-reviewer-verification报告。

### 5.4 保存挂起

保存超时不丢弃候选，不因开放界面而允许并发覆盖。数据管理、暂离心流、可见保存状态和导出入口保持可达；重试必须核对迟到结果。浏览器冻结、强杀、断电和权限失效不承诺无条件写入成功，可靠起点以启动时实际成功保存为前提。
