# 心流开始与异常结算：交互交接

2026-10-16，Designer。已读最新memory索引及其V1.1.0记录、role-boundaries，并核对工程状态。按现有流程局部修改（brainstorming bounded）；PM已传达用户确认，直接供Developer使用，无需新增审批。本文件只定义交互，不编码或操作真实资料，不宣布发布。

## 开始

进入心流先展示项目选择和主按钮“开始心流”，未开始显示“尚未开始”，不能伪装计时已运行。项目为空时按钮禁用，提示“请选择或填写所属项目”。点击后冻结本次项目及开始日期时间，按钮“正在保存开始时间…”，防重复点击。

持久化成功才启动计时并显示“开始时间已保存”及真实开始时间；从已保存的开始时间计算显示，不因等待落盘把开始点悄悄后移。失败保持未启动状态，项目不清空，提示“开始时间未保存，心流尚未启动”，提供“重试开始”。重试的开始时间/会话身份须由Developer保证一致且不重复创建。计时中保存失败持续提示，不只用短暂Toast。

## 异常重开：强制确认实际结束时间

启动加载后发现未结算异常flow，先阻止其他业务操作，显示模态确认。标题“确认上次心流的实际结束时间”。显示项目、完整开始日期时间、最后成功检查点；无检查点时明确“暂无后续成功检查点”，不造时间。

输入标签“实际结束日期与时间”，日期与时间明确到分钟（若系统保留秒则显示精度必须一致）。默认留空，避免默认当前时间导致误计。紧邻说明：**“本次按开始时间至你确认的结束时间计算，包含关闭页面期间；最后检查点仅供参考。”** 显示预览“本次计入：X小时X分钟”，只在输入合法时出现。

规则：必填，不早于开始、不晚于当前；起止比较包含日期，支持跨日及超过24小时，不截断为一天。错误就近显示“请填写实际结束日期与时间”“结束时间不能早于开始时间”“结束时间不能晚于当前时间”，聚焦对应字段，不能仅依赖浏览器控件外观限制。

主操作“确认结束并保存记录”；没有放弃、稍后、恢复继续、关闭叉号。Escape/遮罩/切导航不能跳过；刷新重开仍待结算。限制仅针对异常flow，不擅自改变会议/任务恢复，也不把正常心流完成的分段口径改为全跨度。多个待处理flow逐条处理，未全部成功前不解锁。

## 保存与失败

提交后显示“正在保存工作记录…”，禁用重复提交及时间编辑；不可提前关层/解锁。实际持久化成功且确认同会话未重复结算后，提示“上次心流已记录”，移除对应待结算项；全部完成才解锁。成功提示可见但不要求额外确认点击。

失败保持模态、结束时间和项目上下文，显示“记录尚未保存，请重试或导出待保存数据。” 提供“重试保存”“导出待保存数据”；导出不等同保存成功、不解除强制结算。重试、刷新和重复点击不得多生成记录。权限失效时提供必要“重新连接”入口，范围仅为恢复写入权限，不允许切到空工作区绕过。

## 布局与可访问性

沿用现有浅底弹窗、实底字段、44px最小操作高度；项目及完整时间可换行。窄屏日期/时间纵排，弹窗限定视口内可滚动，错误与按钮不被固定区遮挡。打开焦点落在说明/标题或结束输入；Tab限定在模态内，错误status可播报。无关闭按钮不代表键盘失效，必须保留输入、重试、导出等操作的键盘可达性。

## 实施后设计核对
