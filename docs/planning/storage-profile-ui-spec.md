# 存储与用户资料 UI 规格

## 2026-10-10用户纠正：迁移与编辑身份（优先于下文同主题旧规则）

本次只修订设计，不编码、不发布、不改变版本。已读取INDEX指向的V1.0.0记忆，并补读工作区中的V1.1.0待同步记录；索引尚未指向后者，不把文件存在视为已发布。Git仍有多个角色的进行中修改。用户已明确确认：迁移当前完整数据至空目标；目标已有工作台数据时提示，首版不合并或覆盖。此前讨论的“备份后覆盖”备选已撤销，不得实施。

### 文件夹入口和数据来源选择

浏览器模式按钮为“选择存储文件夹”，目录模式为“更换存储文件夹”。说明“可将当前全部工作区迁移至新位置；原位置的数据保留。” 点击前处理未保存草稿、待保存写入及计时，沿用已有保护规则。随后选择系统目录并检查专用数据文件，不扫描无关文件。

空目标目录：展示“将当前全部数据迁移到此文件夹？”及当前来源、目标目录名、工作区/记录/任务数量、当前用户；列明包含全部用户名称、头像、记录、任务及工作台恢复数据。按钮“取消”“迁移并使用此文件夹”。“迁移”在本产品中是复制、验证后切换保存位置，**不删除原目录文件或原浏览器副本**。

目标含合法工作台数据：显示“此文件夹已有工作台数据”，列出当前/目标工作区、记录、任务数量及最后保存时间。说明“无法将当前数据迁移到已有工作台数据的文件夹。可使用目标数据，或选择空文件夹迁移；不会合并或覆盖。” 操作为“取消”“选择其他文件夹”“使用目标数据”。最后一项明确切换到目标工作台，当前数据保留在原来源。**不显示覆盖、替换或备份并迁移操作。**

目标在空目录预览后出现工作台文件则中止迁移：“目标文件夹已出现工作台数据，迁移未执行”，重新检查并进入非空分支。损坏、空白、未知版本的专用文件同样不是空目标，显示“目标工作台数据无法验证，未迁移或覆盖”，提供取消、选择其他文件夹和原备份恢复入口。选择与当前相同目录提示“已在使用此文件夹”，不重复迁移。

执行状态为“正在迁移当前数据…”→“正在验证目标数据…”。期间禁止重复迁移/资料与工作数据修改，避免冻结快照后遗漏新操作。实际写入、关闭、重新读取及记住来源全部成功后才切换并显示“迁移完成，后续修改将保存到此文件夹”。任一步失败维持原正式源/用户及完整当前数据；持久显示失败阶段、重试/导出，不显示成功。目标可能存在已写副本时说明“目标可能已生成副本，尚未切换”，重试须重新检查目标，不能盲目覆盖。原目录文件或浏览器副本保留，不删除、不修改无关文件；不增加目标覆盖备份流程。

### 编辑当前用户，避免误入新建

第一区标题改为**“编辑当前用户资料”**，副说明“修改姓名或头像会更新当前用户，原有工作记录和任务保持归属。” 字段“显示名称”，主按钮“保存当前用户资料”。当前头像及正式姓名与“当前用户”标记同时可见，不出现“新建”字样。保存以进入编辑时的稳定用户ID为对象，成功后用户总数不变、ID不变、记录/任务不变，仅名称/头像更新；同名冲突报错，不能调用自动后缀命名或建立新用户来绕过。

原“工作区与备份”中单列次级区域**“新建独立用户”**，说明“创建空白工作区，不会修改当前用户资料。” 输入标签“新用户名称”，按钮“新建独立用户”。与编辑区用标题、分隔线及间距明确分开，不复用输入值/提交按钮；新建不是改名后的默认下一步。导入继续明确“导入备份到新用户”，不伪装为更新当前资料。

保存成功提示“当前用户资料已更新，原记录和任务已保留”；失败保持原正式资料和草稿。资料草稿仅在成功持久化后成为迁移快照的一部分；未保存时选择“保存并继续”失败须中止迁移，不迁移未生效资料。选择“放弃更改”则迁移正式旧资料。切用户时不能把A草稿提交给B。

### 本次设计验收增量

- 两用户环境中，给当前用户改名/换头像后，用户数量和当前ID保持不变、既有记录/任务可见；刷新及目录迁移恢复后仍属同一用户。
- 空目录完整迁移；非空合法目标明确提示并提供使用目标数据或另选空目录；无合并/覆盖操作。取消、目标外部修改、写入/验证/来源设置失败不切源。

## 布局、视觉与区域顺序

入口仍为顶栏用户胶囊，标题仍为“用户与数据管理”，保留原dialog，桌面最大520px、视口两侧至少14px、最高视口高度减28px，内部可滚动。顺序固定：

1. **当前用户资料**：72px圆形预览；“显示名称”输入；“选择头像”“移除头像”；图片约束说明；字段错误；“保存资料”。
2. **数据存储位置**：来源、目录名、状态、最近成功读取/保存时间；持续异常/待保存提示；对应操作。
3. **工作区与备份**：原用户列表/切换、新建、导出当前用户备份、导入备份到独立用户。顶部说明“每位使用者都有独立工作区。导入备份会建立新的工作区。”
4. 底部“完成”：仅关闭，不能隐含保存所有草稿。

保留最终Liquid Glass配色及控件体系。区间用标题、24px间距、浅描边分隔，不嵌套多重玻璃卡片。字段和长文使用实底。主要动作蓝色，辅助操作浅蓝；异常文字同时配图标/标题，不只靠色彩。状态时间采用本地日期与时间，并标注“最近成功保存”等语义；无成功时间显示“尚未保存到文件夹”，不显示假时间。非阻塞Toast补充成功，错误持续留在对应区域。

## 用户资料：字段与保存边界

名称预填正式名称，maxlength30，去首尾空格后1–30字符；空名“请输入显示名称”；重名“已有同名工作区，请换一个名称”；按纯文本显示。稳定用户ID不改变。资料区由草稿驱动，顶栏/列表始终由正式资料驱动。

图片说明：“支持 JPEG、PNG、WebP，最大5 MB；将居中裁剪为圆形。” 选择后处理、预览，不更新其他位置；取消选择保持草稿。无图时人物占位，“移除头像”禁用；移除后先显示草稿占位，保存后才更新正式头像。已正式有图但草稿已移除时，可再次选择图片。图片处理时显示“正在处理头像…”，禁用保存与重复选择。

| 条件 | 就近文案 | 结果 |
|---|---|---|
| 类型不支持/伪文件 | “请选择有效的 JPEG、PNG 或 WebP 图片。” | 保持上一份有效草稿 |
| 超过5MB | “图片超过5 MB，请选择较小的图片。” | 同上 |
| 超过1600万像素 | “图片分辨率过高，请选择不超过1600万像素的图片。” | 同上 |
| 解码失败 | “无法读取此图片，请换一张图片。” | 同上 |
| 缩略图仍超过200KB | “无法生成合适大小的头像，请换一张图片。” | 同上 |

保存256×256重新编码副本、上限200KB，去原图元数据，不拉伸，不支持SVG或远程URL；技术校验以产品规格为准。正式值只在当前数据源持久化成功后更新。

“保存资料”：无变化时禁用；有合法变化时启用；提交显示“正在保存…”，同区编辑及涉及用户/数据源切换暂时禁用。成功同步顶栏/列表，清除脏标记，显示“资料已保存”。失败显示“资料未保存，请重试。”加可理解原因；**正式名称和头像保持原值，草稿保留可重试**。不得因目录写排队入队或浏览器缓存成功显示正式生效。重试不能重复创建用户。

### 头像尺寸与可访问性

顶栏28×28px、列表36×36px、编辑72×72px，圆形、object-fit cover、透明图中性底。顶栏整胶囊至少44px高；列表切换和图片操作目标至少44×44 CSS px，不创建嵌套按钮。预览可作为“更换当前用户头像”的按钮，也保留“选择头像”文字操作。人物占位自行绘制，不引入Apple受限素材。

这些尺寸是项目规格，不是Apple统一头像标准；44 CSS px为本Web适配，不能称与Apple的pt物理等同。参考[Apple Buttons HIG](https://developer.apple.com/design/human-interface-guidelines/buttons)。头像邻接名称时作装饰性空alt；独立可点预览有明确可访问名称及外置焦点环。长名顶栏允许省略，输入显示完整可编辑值。

## 存储区域状态与操作

来源标签固定为“当前浏览器”或“已连接文件夹”，后一项展示目录名，不伪造完整路径。目录是整个工作台数据源，不随用户切换。解释“此文件夹保存全部工作区。浏览器可能要求重新授权。”

| 状态 | 主文案 | 可用操作 |
|---|---|---|
| 浏览器模式 | “数据保存在当前浏览器。” | 选择文件夹；原备份操作 |
| 环境不支持 | “当前环境不支持自动文件夹读写，仍可使用浏览器存储和JSON备份。” | 文件夹按钮禁用且说明可见；备份可用 |
| 选择/校验中 | “正在检查文件夹…” | 禁用重复连接/切换，系统选择器可取消 |
| 连接成功 | “已连接”+目录名 | 更换文件夹、改用浏览器存储 |
| 写入中 | “正在保存到文件夹…” | 防重复操作；不更新成功时间 |
| 写失败 | “最新修改尚未保存到文件夹。” | 重试保存、导出备份；显示最后成功时间 |
| 启动等待读取 | “正在读取已选文件夹…” | 全局阻止数据修改及默认初始化写回 |
| 权限失效/启动不可读 | “无法读取已选文件夹，请重新连接或选择其他数据来源。” | 重新连接、使用原浏览器数据 |
| 运行中目录不可达 | “无法访问文件夹，可能已移动或设备未连接。” | 重试连接、更换文件夹、导出备份；保留已加载数据及待保存标记 |
| 损坏/空白/未知版本文件 | “此文件夹中的工作台数据无法读取，未作任何覆盖。” | 重试、选择其他文件夹、现有备份恢复入口 |
| 冲突/其他标签写入 | “数据已在其他位置修改，已停止自动保存。” | 重新加载、导出当前副本；不得自动覆盖 |

“重试连接”不能丢弃未写入变更；重新加载前展示将放弃的变更并先提供导出。读取/迁移/权限失败一律维持原正式数据源与当前用户。状态变化用status/live polite，阻断错误可用alert；不连续播报计时或每次内部写入。

### 连接、切换与目录保护确认

系统选目录后先验证，再在应用内确认。所有确认至少有“取消”；取消不改原来源、不覆盖文件。发现计时仍运行则在操作开始前阻止：“请先结束心流、会议或任务追踪，再切换数据来源。”不自动结束或结算。

| 情况 | 确认标题与正文 | 确认操作 |
|---|---|---|
| 空目录 | “将当前数据保存到此文件夹？”；目录名、全部工作区/记录数量；“将复制全部工作区，原浏览器数据会保留。” | 保存并使用此文件夹 |
| 已有合法数据 | “使用文件夹中的数据？”；双方工作区/记录数量；“将切换数据来源，不合并或覆盖文件夹数据。” | 使用文件夹数据 |
| 换目录 | 复用以上相应确认，并显示当前与目标来源 | 同上 |
| 从已加载目录返回浏览器 | “将文件夹数据保存到浏览器？”；双方摘要；“当前浏览器旧数据会先保留为恢复快照，成功保存后再切换。” | 保存并改用浏览器 |
| 启动目录失权后选择旧副本 | “使用原浏览器数据？”；来源和可获得的最后成功时间；“这可能不是文件夹最新数据。确认后断开记住的文件夹，不修改文件夹内容。” | 使用原浏览器数据 |
| 无可读浏览器副本 | “没有可读取的浏览器副本。” | 创建浏览器工作区、导入备份、取消；创建须明确为新数据源 |
| 上一有效快照恢复 | “恢复上一份有效数据？”；快照时间/来源/数量；“主文件异常，不会自动覆盖。” | 恢复此快照；执行策略由Developer计划定义 |

空目录须实际写入并重新读取验证后才显示已启用。回浏览器须先成功保护旧副本、再保存当前数据、最后切源；任一步失败维持原源，不弹成功。专用数据文件为空白不等于空目录，不显示初始化确认。只读写专用文件，不展示无关文件列表。

## 草稿、关闭与切换

资料草稿或工作录入/补录表单有未保存修改时，关闭资料弹窗、切用户或切数据源须明确处置。只对真正将丢失/错归属的草稿询问，不因打开又关闭而误报。原工作表单关闭资料弹窗后仍在页面且不会丢失时可保留，不必强行清空。

资料草稿确认：“资料尚未保存”，正文“保存后继续，或放弃本次修改。” 操作“继续编辑”“放弃更改”“保存并继续”；保存失败停留原用户/来源及弹窗，显示错误；保存成功后才执行原动作。工作表单用对应名称并提供“返回保存”“放弃更改”，不跨表单代提交。Escape与“完成”使用相同保护逻辑；点击遮罩不自动关闭。切换处理中不接受第二次切换。异步完成不可应用到另一用户。

焦点：打开弹窗移至标题或首字段；错误聚焦相关字段/错误摘要；确认返回后回到触发控件；关闭回顶栏用户按钮。避免原生dialog嵌套失焦，Developer可采用同一弹窗内确认视图或独立可访问确认层。

## 计时恢复提示

目录重开存在成功保存的会话检查点时显示“发现未完成的计时”。逐项列类型、项目、已保存用时、检查点时间；说明“计时已暂停，关闭页面期间不计入。仅恢复最近成功保存的用时。” 操作“恢复计时”“放弃本次计时”。放弃明确“不生成工作记录”；取消/稍后保持暂停，不自动新起会话。结算写入期间显示“正在保存工作记录…”，成功后才“已记录”；失败显示重试/导出，不重复结算。多会话呈现及底层去重由Developer按规格落实。强制终止可能丢失最后一次成功检查点后的变化，应在说明中可见，不作零丢失承诺。

## 窄屏与验收清单

≤560px：沿用dialog18px内边距；两区纵排，头像与名称可上下排列；操作按钮自动换行且至少44px高；来源长名换行，确认摘要纵排。≤360px：保存/确认按钮各整行，无横向滚动。200%缩放优先重排、垂直滚动，不固定底栏遮挡内容。图片不随容器拉伸；减少透明度/高对比规则沿用。

Designer实施后检查：28/36/72尺寸、区序、正常与错误文案、正式/草稿隔离、保存失败不生效、未保存确认、切源保护、窄屏与缩放、焦点。Reviewer独立验证权限恢复、实际落盘/读取、坏文件保护、冲突/快照、三类计时检查点及去重、新旧备份。未实测平台须明确；Designer不以UI检查替代版本验收或远端核对。
