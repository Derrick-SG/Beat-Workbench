## 布局候选与推荐

1. **推荐：保留原弹窗，纵向分区。** 顺序为“当前用户资料”→“数据存储位置”→“工作区与备份”（原功能）→“完成”。保持原宽度上限520px与视口内滚动；新增操作独立保存，底部“完成”只关闭弹窗。优点是入口不变、范围集中；代价是高度增加。
2. 全页设置：长内容更宽松，但新增页面和导航负担，不建议本轮采用。
3. 弹窗内双标签页：高度较短，但隐藏目录异常与已有工作区操作，增加定位成本，不建议本轮采用。

保持现有浅蓝、实底表单、玻璃浮层、圆角、按钮层级与移动换行规则；不新增账号登录、云同步、多设备同步或通用文件管理器。

## 当前用户资料区

头像预览在左，用户名输入与图片操作在右；窄屏可换行。标签“显示名称”，预填当前名，沿用30字符上限；去除首尾空格、空名报错。重名建议明确报“已有同名工作区，请换一个名称”，不静默改名；由PM最终统一现有新建/导入的自动重名策略。名称是本地工作区标签，不表达实名或在线身份。

图片操作“选择头像”“移除头像”；选择后先本地预览，点击“保存资料”才提交用户名和头像。取消文件选择保持原草稿；移除先恢复默认占位、保存后生效。未保存关闭或切用户时，提供“继续编辑 / 放弃更改”，不自动把草稿写给其他用户。保存失败保持草稿和原资料，区内显示原因，允许重试；成功更新顶栏与工作区列表，不重置记录/任务。文件只作本地处理，界面用“选择头像”避免误导为服务器上传。

建议先接受JPEG/PNG/WebP静态图片，文件上限5MB；解码后生成256×256头像副本，不保存原始大图。居中裁成正方形并用圆形遮罩；文字提示“将居中裁剪为圆形，请选择主体居中的图片”。不增加裁剪编辑器。实际像素/格式/压缩限制交Developer评估后由PM确认。无效格式、文件过大、无法解码分别就近报错；不清除原头像。透明图片使用中性底；无头像显示通用人物占位，不用未经授权的Apple素材或SF Symbols资源。

| 使用处 | 建议显示尺寸（CSS px） | 操作约束 |
|---|---|---|
| 顶栏用户胶囊 | 28×28 | 整个胶囊可点击，最小44px高；头像不再形成嵌套按钮 |
| 工作区列表 | 36×36 | 头像只标识用户；独立切换按钮点击区域至少44×44px |
| 资料编辑预览 | 72×72 | 可点击选择图片，但旁边保留明确文字按钮；键盘可访问 |

上述28/36/72是本项目密度和层级建议，**不是Apple规定的统一头像尺寸**。Apple Buttons指导一般点击区域至少44×44pt（visionOS另有尺寸）；本Web工程建议44×44 CSS px是设计适配，不声称pt与CSS px跨设备物理等同。头像视觉尺寸和点击区域分开。来源：[Apple Buttons HIG](https://developer.apple.com/design/human-interface-guidelines/buttons)。圆形图片object-fit cover，固定比例；焦点环在遮罩外。邻接已有用户名时头像可作装饰性空alt；独立图片按钮需“更换当前用户头像”的可访问名称。截断只用于顶栏，输入和资料区可读完整名称。

## 数据存储位置区

固定展示：当前位置、权限/连接状态、最近成功读取/保存时间、相关主操作。位置默认“当前浏览器”；选择目录后展示可读目录名，不虚构浏览器无法提供的完整路径。成功保存时间只在实际写入完成后更新；浏览器保存与目录保存要分开标注，不能用一个绿点掩盖目录失败。

建议目录为应用级设置，目录内保留所有独立工作区及资料；切用户不会改目录，目录切换相当于切换整个数据集。若PM选择每用户独立目录，须重新设计标签和切换风险，不能实现时暗改语义。

候选存储路径：

- 支持目录授权的浏览器：用户通过系统选择器选择目录；下次启动尽力恢复访问，权限失效时显示“重新授权”。不能承诺每次无交互自动读取。
- 不支持目录访问的浏览器/入口：明确“当前环境不支持自动目录读写”，保留浏览器存储和现有JSON导入导出；手动导入不能冒称已满足自动读取需求。
- 若用户要求任意环境始终自动读目录：由PM与Developer评估桌面运行方案，这是交付方式决策，Designer不以界面文案掩盖能力差异。

具体可行性、权限记忆、目录格式与并发策略须Developer针对用户确认的环境验证；本报告不承诺某浏览器/协议的支持状态。

### 首次连接与更换目录

“选择文件夹”→系统选择器→检查权限及应用数据→展示将执行的结果→确认后启用。用户取消选择不改变位置。空目录提示“将把当前工作台数据保存到此文件夹”；已有合法数据时提示“此文件夹包含N个工作区、N条记录，切换后显示该文件夹的数据”，再选“使用此文件夹 / 取消”。**不默认合并或覆盖两套数据。** 原浏览器数据保留，迁移成功之前不删除、不宣布目录已启用。更换目录沿用同一流程；“改用浏览器存储”也需先明确数据来源并成功保存，不能仅断开目录导致数据消失。

首次迁移为当前全部工作区还是仅当前用户，是PM待确认的范围；推荐全部工作区，以匹配应用级目录。目录数据是否包含头像需纳入格式兼容审查，不能默认旧JSON已支持头像往返。

### 状态与异常呈现

| 状态 | 区内文案/操作 | 设计约束 |
|---|---|---|
| 未设置 | “数据保存在当前浏览器”；选择文件夹 | 原JSON备份入口可见 |
| 检查中/读取中 | “正在检查文件夹…” | 临时禁用重复连接；未确认前不切换数据 |
| 已连接 | 目录名、“已连接”、最近成功保存；更换文件夹 | 不说云同步；状态不只靠颜色 |
| 下次启动待授权 | “需要重新授权才能读取已选文件夹”；重新授权 | 不能把旧浏览器缓存标作目录最新数据；重新授权前不覆盖目录 |
| 目录不可用 | “无法访问文件夹，可能已移动或设备未连接”；重试/更换 | 保留已加载数据并标注最后成功时间；不自动新建空数据覆盖 |
| 数据不合法/版本不兼容 | “无法读取此文件夹中的工作台数据”；重试/选择其他 | 不自动初始化或覆盖；提供原JSON恢复入口 |
| 已有数据与当前数据不同 | 显示数据摘要、明确使用来源 | 不隐式合并；切换前处理未保存资料和计时 |
| 保存失败/空间不足 | “最新修改尚未保存到文件夹”；重试/导出备份 | 持续显示待保存状态；若仍可用，浏览器副本单独说明，不能假称双份已保存 |
| 环境不支持 | “当前环境不支持自动目录读写”；JSON备份替代说明 | 自动读取仍为未满足项，不静默降级为下载文件 |

目录失败等持续异常放在区内，必要时顶栏存储状态也提示；Toast只作补充。运行中的心流/会议/任务追踪在目录数据切换前必须明确处理，不能沿用旧版切用户风险；由PM确定“先结束计时再切换”或取消切换，推荐先阻止切换并指引完成计时。
