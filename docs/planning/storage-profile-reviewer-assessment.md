## 理解与待确认边界

用户希望在数据管理中选择数据文件夹，下次打开读取该目录；支持修改用户名和上传圆形头像，尺寸参考 APPLE。主要运行环境由 PM 确认中。本文件是独立风险和验收输入，不代替 PM 的范围决策、Designer 规格或 Developer 技术方案。采用 brainstorming 实施前评估，目录持久化属于新存储边界；没有据此启动实现或原型。

方案批准前需要明确：

- 主要浏览器、操作系统、HTTP/HTTPS 或单 HTML 入口；是否要求跨浏览器/跨电脑和无需任何再次授权。
- 文件夹是唯一主存储、浏览器数据的同步副本还是手动备份位置；首次绑定已有数据、空目录、改选目录时谁覆盖谁。
- 文件夹包含全部用户还是仅当前用户；启动自动恢复哪个用户；目录文件结构、数据版本、冲突和迁移策略。
- 用户名重复/空白/长度规则；头像支持格式、原文件大小、解码尺寸、裁剪方式、移除功能及具体显示尺寸。
- 头像是否随 JSON 导出、目录同步及用户迁移；旧 v3 备份如何导入、旧版本是否仍能读取新备份。

## 已核实的平台边界

Chrome 官方说明目录句柄可以保存到 IndexedDB，但恢复句柄后须检查权限；权限请求依赖用户操作。MDN 将 showDirectoryPicker 标为有限支持、安全上下文功能，且要求瞬时用户激活。因此“自动读取”只能在已确认支持的运行入口、句柄可恢复且权限有效时承诺；权限为 prompt/denied 时应显示重新授权入口，不能自动弹选择器或把未授权误判为空目录。

来源（2026-10-09 查阅）：[Chrome File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、[MDN showDirectoryPicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)、[MDN queryPermission](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemHandle/queryPermission)。这些是平台文档证据，未在当前应用进行权限实测。不能把浏览器内部存储/OPFS 说成用户选定的可见文件夹，也不能承诺输入路径字符串即可读取任意目录。file 入口及企业策略必须实际验证，不能由 localhost 测试外推。

## 风险及必须具备的验收条件

| 编号 | 风险 | 可验收条件 |
|---|---|---|
| D1 | 重开时权限不持久、句柄丢失、API 不支持 | 首次用户操作选择/授权；重开在权限有效时加载，需授权时清楚提示并可操作；拒绝、取消、不支持均不崩溃、不假报已连接。 |
| D2 | 读取失败被当作空数据，然后回写清空原数据 | 目录未就绪时阻止自动回写；区分不存在、空文件、解析/模式失败、权限错误；全部验证成功后才替换内存活动数据。失败前后浏览器及目录原数据保持不变。 |
| D3 | 首次绑定或改目录时无意覆盖另一组数据 | 按批准的导入/迁移规则展示来源和目标；已有目标不得静默覆盖，取消不改活动用户/目录；空目录初始化与旧数据恢复是不同状态。 |
| D4 | 写入/关闭失败、磁盘满、只读、断开导致假成功 | 等待写入及关闭完成才标“文件夹已保存”；失败保留未同步状态、可恢复编辑和最后有效文件；可重试/导出；不得只因浏览器副本成功就声称目录成功。 |
| D5 | 异步写乱序、关页时未完成、多标签覆盖 | 确认排队/冲突策略；快速连续编辑最终文件为最新版本；重新读取检测外部变化，不静默覆盖；关页尚有写入时说明边界，不承诺仅靠 unload 必达。 |
| D6 | 新文件格式不兼容、文件被截断或写一半 | 对数据结构和版本作检查；损坏文件不得触发空白保存；新 schema 的字段迁移和备份/回退策略可验证。不得未经验证声称文件系统原子写保证跨全部环境。 |
| P1 | 改用户名改变存储路径，造成丢数据或串用户 | 保持稳定用户 ID；改名不改记录/任务/目录归属；刷新、导出再导入后行为符合规格；所有可见名称及时一致，重名处理清楚。 |
| P2 | 名称含 HTML、路径字符、超长字符 | 按已批准长度规则验证、作为纯文本显示；不以用户名直接拼任意文件路径；不能穿越目录或注入标记。失败不损坏旧名称。 |
| P3 | 伪图片、损坏图、巨幅解码、SVG 活动内容 | 不只相信扩展名/MIME；实际解码及体积/像素限制；明确允许格式，若无必要不接收 SVG；拒绝时保留旧头像，提示原因。限制值由方案明确，不能由 Reviewer 随意认定。 |
| P4 | 圆形裁剪变形、EXIF 方向错误、缺头像不可用 | 正方形/长方形/透明/带方向图片按规格裁剪不拉伸；圆形边界、目标尺寸、缩放和默认头像/替代文本满足 Designer 明确标准。不存在泛指的单一“APPLE 头像尺寸”可直接验收。 |
| P5 | 头像配额增长、对象 URL 失效、切用户串图 | 头像随稳定用户 ID 隔离并持久化；刷新/切用户/目录加载后仍正确；不将临时 blob URL 当永久资料；替换与移除不破坏记录和其他用户。 |
| P6 | 用户图片泄露或备份遗漏 | 本地选择不上传第三方；共享 ZIP、Git 提交、日志和测试证据无真实头像/工作记录；是否进入 JSON 和目录备份须明确并验证。 |

当前 src/app.js 的用户清单、记录和任务使用不同 localStorage 键；导出 v3 仅含 profile.name、records、tasks。现有用户切换/新建/导入会直接更换活动数据，原版已有计时归属风险。此次目录异步读取及资料编辑不得扩大该风险：读写期间切用户应取消/隔离旧请求，迟到结果不得覆盖另一用户；计时中改名应仍归属同一 ID。若需限制计时中切换，交由 PM 明确本次范围，不能将所有 R1–R8 隐式纳入修复。

## 后续独立验收测试矩阵

1. 在确认的主要环境执行首次选择、正常写入、刷新、完整关闭重开；记录版本、协议、权限状态及文件实际内容。自动化替身仅覆盖状态机，不替代系统权限实测。
2. 取消选择、拒绝/撤销授权、清浏览器句柄、目录移动/删除、只读或断开、API 不支持；操作前后对浏览器数据与目录文件做数量/字段或哈希对照。
3. 目录已有有效/空白/损坏/未知版本文件，浏览器另有不同数据；首次绑定、改目录与取消；验证不静默合并或覆盖。
4. 连续编辑、并行写入、多标签、外部修改、写入中关页及重试；故障注入和真实目录至少各覆盖一类，核对最后成功版本与未同步反馈。
5. 两用户分别改名/上传头像/切换/刷新；目录读写进行中切换及 JSON 迁移；原 ID、记录、任务和计时归属保持正确。
6. 合成图片覆盖正常 JPEG/PNG、长宽图、透明、方向元数据、伪后缀、损坏、超大小/超像素、未允许格式；拒绝无残留、旧头像不丢。
7. 新旧 JSON、旧浏览器数据升级与目录文件恢复；记录/任务完整，资料字段按确认的兼容策略处理；无真实个人数据进入仓库。
