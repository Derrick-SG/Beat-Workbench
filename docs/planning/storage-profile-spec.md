# 自定义存储与用户资料规格

日期：2026-10-09。状态：用户已同意纯网页分级方案及上一轮方案摘要；本书面规格待用户审阅，尚未授权据此开始实施。当前已交付版本仍为 V1.0.0。

## 目标与范围

在现有“用户与数据管理”弹窗增加“当前用户资料”和“数据存储位置”，保留工作区管理及备份入口。新增自定义目录保存与重开读取、当前用户改名、圆形头像。不增加服务器、云同步、登录或桌面程序，不合并苹果字体需求，不全面修复原版历史缺陷。

依据三个角色评估：`data-management-design-assessment.md`、`storage-profile-developer-assessment.md`、`storage-profile-reviewer-assessment.md`。详细设计由 Designer 负责，技术实现和实施计划由 Developer 负责，独立验收由 Reviewer 负责。本文收敛产品行为和验收边界；若技术方案需偏离本文，先由 PM 汇总影响。

## 纯网页兼容约定

- 基于真实能力检测启用目录模式，不仅按浏览器名称判断。主要验证环境为支持相关 API 的桌面 Chrome/Edge，以及稳定的本地 HTTP 或 HTTPS 入口。
- 用户主动选择目录并授权后记住目录；下次启动恢复目录授权仍有效时自动读取。需要重新授权时显示“重新连接”，不能承诺绕过浏览器权限或每次无操作读取。
- Safari、手机、受限浏览器和无法稳定记住句柄的 file 入口保留浏览器存储及手动 JSON 导入导出，明确不支持自动目录读写。file 入口能否启用目录模式依据实测和能力检测，不能从 HTTP 结果外推。
- 不包含手机访问桌面本地服务、公网部署或跨设备同步。主流环境必须能使用核心浏览器存储模式；实际未测环境须写明，不虚报全平台验收。

## 存储数据与切换

- 一个目录对应整个工作台，包含全部用户资料、记录、任务和当前用户标识；目录配置是应用级，不随用户切换。目录只操作专用工作台数据文件，不扫描或修改无关文件。
- 数据源明确分为“当前浏览器”与“已连接目录”。保留旧浏览器数据，不自动删除。目录副本成功写入前不能显示保存成功。
- 空目录：先说明将复制当前全部工作区数据，用户确认后写入并重新读取验证，再启用目录模式。
- 已有合法工作台数据：先展示工作区/记录摘要，用户确认后切换到目录数据；不自动合并，不用浏览器旧副本覆盖。
- 已有空白、损坏或不支持版本的工作台文件：停止切换，不自动初始化或覆盖，提供重试/换目录/备份恢复入口。
- 取消、拒绝、读取失败或迁移失败：原数据源、当前用户及原数据保持可用；已连接源启动未完成前禁止数据修改和默认数据回写。
- 更换目录沿用上述确认流程。改回浏览器模式须明确使用当前已加载数据的浏览器副本，成功保存后才切换；不得静默回到旧数据。
- 心流、会议或任务追踪计时进行中禁止切换数据源；未保存表单/资料草稿先保存或明确放弃，不能丢弃而不提示。切换用户时也不得让旧异步请求写入另一用户。

## 保存、恢复与冲突

- 启动先确定数据源并验证数据，再允许录入；读取错误不等同空数据。
- 写入排队，快速连续操作不能导致旧快照覆盖新快照。只在实际写入及关闭成功后标记“已保存”；失败保留待保存状态，提供重试和导出。
- 保存状态区显示目录名、连接/权限状态、最近成功读取或保存时间；不伪造完整系统路径，不把浏览器副本成功当作目录保存成功。
- 目录数据有明确格式、独立 schema 版本、稳定工作区/用户 ID 和修订标识。旧版浏览器数据只读捕获后迁移；新格式及校验细则由 Developer 在实施计划中明确。
- 同源多标签防止同时写入；发现外部修改或修订冲突时停止自动覆盖，保留双方数据并提示重新加载或导出。不能承诺跨浏览器/设备的强并发锁或断电绝对原子性。
- 不依赖关页事件完成异步落盘。本阶段纳入三类计时的恢复检查点与去重：目录模式在页面正常运行时目标每 15 秒保存进行中计时的已用时和稳定会话标识；后台节流或冻结时不保证间隔，恢复以最后成功检查点为准；重开暂停计时并提示恢复或放弃。恢复只计入最近成功检查点前的已用时，关闭网页期间不计时；放弃不生成工作记录。用户主动完成时须等待写入结果；相同会话 ID 至多结算一次，写失败后重试或重开先核对已结算 ID。强制终止可能丢失最后一次成功保存后的变化，界面/说明须如实表述。
- 保留可恢复的上一份有效快照，损坏主文件不自动覆盖；恢复须展示来源并确认。具体文件布局、保留上限、写入顺序和失败策略由 Developer 计划列明并交 Reviewer 检查。

### 失权退出与浏览器副本保护

启动无法读取原目录时，提供“重新连接”和“使用原浏览器数据”两个明确入口。后一项仅加载此前浏览器保存的数据，展示来源与时间，不假称目录最新数据；原目录保持不写入，记住的目录配置可在用户确认后断开。没有可读浏览器副本时，用户可明确创建浏览器工作区或导入备份，不用启动中的空内存覆盖任何已有副本。

从已加载目录转回浏览器模式时，先展示双方用户/记录摘要并确认将保存目录数据。原浏览器数据先保留为独立恢复快照，再成功保存新浏览器副本，最后切换。任何一步失败不启用新源。用户可取消以继续使用目录；不得无提示合并、覆盖或删除原浏览器数据。

## 用户名与头像

- 改名只更新显示名称，稳定用户 ID、记录、任务归属不变。首尾去空格，1–30 字符，拒绝已有其他工作区的同名；按纯文本显示。
- 用户资料先预览，点击“保存资料”才生效；取消或失败保留原资料。未保存关闭/切换须提示；成功同步顶栏、列表及备份资料。
- 目录模式资料保存须实际写入成功后才成为正式资料并更新顶栏/列表；失败保留原正式姓名和头像及编辑草稿，不把乐观更新当作成功。浏览器模式同样等待持久化成功。
- 可选择或移除头像。接受 JPEG/PNG/WebP，原文件不超过 5 MB，解码不超过 1600 万像素；拒绝 SVG、远程地址、损坏图片和伪图片。
- 居中正方形裁剪，不提供裁剪编辑器；保存 256×256 的重新编码缩略图，编码体积不超过 200 KB，无法满足则提示换图，不保留原图元数据。长宽图不拉伸，透明图有中性底。
- 按 Designer 建议：顶栏头像 28px、工作区列表 36px、编辑预览 72px，圆形遮罩；可点击区域至少 44×44 CSS px。上述是项目规格，不宣称 Apple 存在统一头像尺寸。缺图显示自绘人物占位，操作有明确文字和键盘焦点。
- 头像仅本地处理，随对应用户、目录数据和新备份保存；不上传第三方，不进入项目 Git 或分享包。

## 备份兼容

保留旧 v3 和纯记录数组导入，缺头像时使用默认占位；单用户导入继续建立独立工作区，不隐式合并。含头像的新备份标注新格式版本，并保留姓名/记录/任务；具体版本由 Developer 写入计划。旧 APP 无法往返保留头像，说明中明确。目录全工作台文件与单用户备份是不同用途，不混用。

## 验收与交付

1. Reviewer 实测目录首次连接、有效授权重开自动读取、需授权/拒绝/取消/不支持分支，并检查实际文件内容。权限 API 替身测试不能替代真实目录实测。
2. 验证空目录迁移、已有数据切换、损坏/未知格式、写失败、连续写和冲突不静默覆盖；测试数据使用合成资料。
3. 验证两个用户改名、头像选择/移除、刷新、目录恢复及新旧 JSON 兼容；拒绝图片不破坏旧资料。
4. 验证三种计时中的数据源切换限制、会话恢复及去重，原记录/报告核心路径回归。
5. Designer 检查顶栏、弹窗、列表、窄屏/缩放及异常状态；Reviewer 报告通过项、缺陷和未覆盖环境。没有检查结果 PM 不宣布完成。
6. 更新开发说明、兼容矩阵及离线分享包；已批准的新功能会改变原版字节等价测试，Developer 须保留原版 reference 并改为合理的回归/打包验证，不简单删除保护性检查。
7. 本阶段不提前提高版本号；功能验收后由 PM 确认发布编号。每次上传按 AGENTS.md 更新版本化累计 memory 和索引并同提交上传，先记录待同步，推送后实际核对。
