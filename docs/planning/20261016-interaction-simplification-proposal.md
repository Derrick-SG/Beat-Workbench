## 推荐原则

一次明确动作直接执行，不再询问“确定吗”。默认继续仅指用户已点击具名动作后的常规可逆操作，不是后台猜测意图、自动丢草稿、切来源或填写人工结束时间。保留实际落盘确认、幂等与计时限制；这些内部保护不需要变成额外弹窗。

## 步数对照

步数仅计应用内动作/确认，不计填字段、进入页面及系统权限弹窗；不同前置状态分列，避免夸大减少。

| 路径 | 当前 | 建议 | 变化 |
|---|---|---|---|
| 开始心流 | 选项目后点开始1次，无confirm | 原样，启动按钮在运行后同位置变“完成并保存” | 1→1；减少两颗相似按钮 |
| 正常结束 | 完成1次，无confirm | 原样，等待成功后完成 | 1→1 |
| 异常flow结算 | 人工填结束后保存1次 | 原样；项目/时间/用时就地展示 | 1→1；不得默认结束时间 |
| 资料编辑保存 | 保存1次；离开另有完成 | 点“保存资料”成功直接关闭；失败原地 | 2→1（以保存并退出为目标）；需继续设置者可再打开 |
| 新建用户 | 新建1次 | 保留独立“新建用户”，不加确认 | 1→1；不得与改名合并 |
| 空目录迁移 | 选目录→应用内迁移确认 | 入口改“迁移当前数据到文件夹”，旁说明保留旧数据；系统选空目录后直接执行 | 2→1；系统授权仍按浏览器要求 |
| 非空目录 | 选目录→选择目标数据/另选 | 原样展示双方摘要，“使用目标数据”一次执行 | 2→2；不覆盖不合并 |
| 回浏览器模式 | 点入口→confirm | 入口显示预期来源/数量及保护旧副本说明，按钮“保存当前数据到浏览器并切换”，一次执行 | 2→1；有待丢数据另走冲突确认 |
| 恢复原浏览器独立副本 | 恢复入口→选副本→confirm | 入口→含来源/日期/数量的列表，每行“恢复此副本”直接执行 | 3→2；存在待保存变更时保留一次整合确认 |
| 使用旧浏览器数据且有待保存变更 | 入口→丢弃confirm→旧来源confirm | 同一确认层显示旧副本时间+将丢变更，提供导出/返回/“放弃修改并使用此副本” | 3→2；必要知情合并在一次 |
| 重新加载，无草稿无待保存 | 点入口→丢弃confirm | 点“重新加载”直接执行 | 2→1 |
| 重新加载，有未保存变更 | 点入口→confirm（资料草稿还可能再问） | 汇总所有将丢弃内容，一层明确确认 | 多层→1层；不能默认丢弃 |
| 重试保存/导出 | 各1次，无confirm | 各1次，统一就近位置 | 1→1；减少同屏重复入口 |

资料保存并关闭是明确交互变化，须PM合入最终局部方案，不能默默实施；保留“取消/关闭”且有草稿时只问一次。另一选择是保存仍留在弹窗（步骤不减但连续设置方便），推荐前者以回应操作简化。

## 按钮收敛

- 心流同一个主动作位置表达未开始/保存中/运行/结束保存中/重试，另保留次级“暂离”；不把“暂离”变暂停。两种入口分别是导航和工作动作，不硬合并。
- 资料区仅“选择头像”“移除”“保存资料”，标题明确编辑当前用户；新建独立次级区保留，禁止把名字输入复用为新建。
- 存储正常态仅主要“迁移到文件夹”或“更换文件夹”；“其他恢复方式”一个展开区收纳旧副本/上一有效快照/重新加载。失败态自动展开对应“重试保存”“导出待保存数据”，不另展示多个同义“恢复/重新连接/重试”。权限失效用“重新授权并重试”；写入仍活跃时禁用重试并说明，导出可用。
- “导出当前用户备份”与“导出全工作台待保存数据”范围不同，不能合并成一个无说明的导出。正常只展示用户备份；错误出现全工作台导出，并显式标注范围。

## 多会话可理解性

强制flow逐条结算保留，标题加“待确认心流 1/N”，固定显示所属用户/项目/开始时间；成功自动进入下一条，不加成功确认，不提供“全部按当前时间结束”。没有新增计时种类或自动合并历史会话。正常页面明确“当前正在计时：项目名”，有运行会话时主入口返回该会话，不再次创建。会议/任务存在多个旧检查点时用同一列表标类型、项目、日期，按钮直接绑定具体会话，避免用户不知道恢复哪一次；放弃仍明确不产生记录。

## 必须保留的知情

已有目标数据来源切换、损坏恢复写回、丢弃未保存、不可逆删除和人工结束时间，不用默认同意替代。新需求也不授权目标覆盖或合并。将摘要说明放在具名动作旁后，一次点击执行即可，避免选择完同样内容又弹泛化confirm。数据/权限检查失败按原安全规则停止，不因少弹窗放宽保护。

推荐先做按钮状态收敛和重复confirm整合，再检查主路径是否实际减少；不扩展自动保存资料、撤销系统或全新设置页面。最终由PM集中呈现批准后的范围；Developer实现，Designer核对，Reviewer独立验证。
