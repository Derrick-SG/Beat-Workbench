# 异常心流自动结算：最小交互交接

2026-10-19，Designer。已读最新INDEX/memory与角色边界。本次用户明确纠正覆盖此前人工end全跨度设计及其验收结论；不是新增可选模式。按现有流程局部改动，不编码、不操作真实数据、不定新版本。交由PM协调Developer，实测由Reviewer负责。

## 重开流程

读取持久化会话后自动结算，不弹人工结束确认、不提供end输入、不等待用户逐条点击。结束依据最后成功保存的检查点，工时按已保存实际工作分段计算，不把关闭后的间隔或未成功保存的内存时间算入。若只有开始检查点，真实可计时长可能为零：不得伪造最短一分钟或自行改为当前时间，交Developer按数据模型保留可追溯零时长会话/记录，不能丢失起点。

恢复处理中在可见状态区显示“正在保存上次心流记录…”，明确正在处理而非已经成功。实际持久化成功才显示“上次心流已自动记录”，下方列项目（空项目显示“未归类项目”）、开始时间、最后成功检查点和计入用时。说明“仅计入最后成功保存的工作时间，关闭后间隔不计入；最后检查点后的未保存变化可能无法恢复。” 多会话一次汇总“N次心流已自动记录”，不逐条弹确认或新增成功确认按钮。

结果使用现有记录列表/状态提示呈现，不新增页面。普通提示可关闭，记录本身保留；不能把关闭提示当结算成功条件。顶部状态或记录列表应能重新看到结果，不能只靠短Toast。实际是否保持启动期间全局修改锁由Developer保证数据一致性，等待结束后正常进入。

## 失败与可恢复性

失败持续显示“上次心流记录尚未保存”，保留原会话、成功检查点及待保存副本，给“重试保存”“导出待保存数据”。不出现“确认结束”“恢复计时”“放弃会话”或人工end入口。重试使用同一会话ID、同一检查点结算，成功才移除待结算会话；导出不等同成功，幂等不生成重复记录。

可恢复业务锁不应变成死页：重试、导出及必要重新授权必须可见且键盘可达；不能靠改用空源绕过/清掉旧会话。正在进行的写入显示等待状态，超时说明写入可能仍在进行，不宣称取消成功。多个会话部分成功时分别标识，成功项不重做，失败项不被汇总成功文案掩盖。

## 未选项目

空项目不阻断自动结算；显示“未归类项目”是展示占位，不要当作用户真实项目字符串写回并与同名真实项目混淆。记录保留原用户、会话身份及已保存任务。用户随后通过现有编辑记录入口补选/修改项目，更新同一条记录，不创建新用户或重复记录；无强制补项目弹窗。标题可沿用心流内容或“心流工作”，不凭空生成成果。

## 关闭时反馈与原路径

不能显示“关闭时已保存”或依赖关页异步操作保证成功。正常运行只展示最后一次真实成功检查点及未保存错误；下次启动依据持久化数据处理。顶部点击立即捕获起点、运行中补项目、同表单快速会议右侧主按钮等已确认路径不扩大调整。正常完成分段口径保留；不将meeting/task异常规则自动一并改写。

## 核对清单

删除旧强制end层触发和相关文案；自动结算结果含时间来源与用时；关闭间隔排除；只有开始检查点不伪造时长；空项目同条记录可编辑；写失败重试/导出可达、重开不重复；多会话部分失败准确。Designer核对交互/文案，Reviewer独立核实际工时、落盘与幂等。旧人工end报告仅作历史证据，不能用来宣称新模型通过。
