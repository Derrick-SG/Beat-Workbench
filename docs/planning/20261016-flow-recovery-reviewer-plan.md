# 2026-10-16 Reviewer：心流可靠启动与异常结束验收计划

角色：独立验证，不修改产品实现，不操作4173个人数据，不提交上传。用户最新确认的异常flow恢复全跨度规则优先于此前仅检查点恢复规则，正常分段和会议/任务规则不变。

## 已复现证据

- 当前生产beginSession在browser模式直接返回，合成执行commit次数0，浏览器模式无可靠会话起点落盘。
- 当前生产blockWorkspaceMutation在phase=saving时拦截open-data-dialog、retry-save、close-data-dialog；挂起写入可使恢复入口不可达。未证明用户原现场存储确实挂起，不声称唯一根因。

## 核心验收

1. 选项目启动：browser/directory分别确认稳定session ID、实际start、project在repository重新读取可见后才激活计时。取消、失败、挂起不显示已开始；临时会话明确不保证重开恢复。
2. 长时与队列：24/25/49小时及重复点击/检查点，提交队列和待保存快照有明确上限；慢写/永不完成/失败不无限排队。数据管理、重试、导出和错误提示可达，迟到写完成不能覆盖后续源或新修订。超时不是保证底层IO已取消。
3. 异常重开：browser/directory皆识别flow，强制确认层阻挡背景操作、Esc/取消/切用户/切源，刷新重开仍需确认；未完成保存不能解锁。多个旧sessions保持稳定归属且兼容旧格式。
4. 人工结束：开始<=结束<=当前，明确完整日期时间，验证等于开始、跨午夜、跨周/月/年及未来/无效输入。等于开始的零时长处理必须与模型正工时校验协调，不允许无法结束的死循环。
5. 恢复结算按实际start至人工end全跨度计工时，含退出间隔且UI明示；日周月年/项目统计与保存导出导入一致。正常工作分段不变，会议与任务恢复不被改写。
6. 幂等：重复确认、双击、写失败重试、写已完成但回执丢失后重开，仅一条记录，成功才清会话/解锁。保留原记录和其他用户资料，不静默回退旧源。

证据分层：生产函数与controller/repository合成故障测试，临时磁盘回读，隔离浏览器UI。原生目录权限不可控时明确未测，不以替身冒充。候选冻结后复核打包与最终文档，不提前声明通过。
