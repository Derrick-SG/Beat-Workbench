# 节拍工作台：源码恢复版

保留 2026-09-22 分享版的界面和功能，机械拆出可编辑源码，并提供零依赖本地运行与单 HTML 打包。首版未修改业务逻辑，也未修复原版历史风险。独立验收由 Reviewer 执行，版本完成由 PM 判定。

## 文件入口

- `src/index.html`：开发页面入口。
- `src/styles.css`：原版内联 CSS，保留顺序与内容。
- `src/app.js`：原版内联 module 脚本，保留逻辑与内容。
- `scripts/serve.mjs`：只在 127.0.0.1 监听、只提供三个源码资源的开发服务器。
- `scripts/build.mjs`：将源码内联成 `dist/节拍工作台.html`。
- `reference/2026-09-22/`：不可修改的原始资料。
- `tests/`：打包基线、JSON 数据和时间统计、本地服务检查。
- `docs/recovery/`：各角色评估、实施计划及 Developer 交付证据。

## 本地运行

需要 Node.js 22 或更新版本和现代浏览器。本次使用现有 Node 24.19.0；无需安装 npm 包，未提供后端或云同步。

在项目目录打开终端：

```powershell
node scripts/serve.mjs
```

浏览器打开 http://127.0.0.1:4173/ ，修改源文件后刷新。Ctrl+C 停止。端口占用时可先执行 `$env:PORT = '4174'` 再启动；端口变化也会改变浏览器数据空间。

**不要直接双击 `src/index.html`**：外部 module 在 file 地址下可能被浏览器拦截。双击使用请打开打包后的单文件。

## 重新打包与分发

```powershell
node scripts/build.mjs
```

输出 `dist/节拍工作台.html`，可单独复制、离线双击运行，无需随附源码。以 `src/` 为编辑来源；不要直接编辑 dist 后期待改动被保留。打包器以 UTF-8 保留源码内容，不压缩、不转译，不读取 reference 作为构建输入。

## 开发验证

```powershell
node --test --test-isolation=none tests/*.test.mjs
node --check src/app.js
node scripts/build.mjs
```

若本机有 npm，也可使用 `npm start`、`npm test`、`npm run build`；本次环境未提供 npm，因此以以上 Node 命令验证。

测试覆盖：打包产物与原版字节一致、JavaScript 语法、v3 JSON 逐字段导出再导入、旧数组/分类兼容、独立用户与旧用户数据保留、空备份/损坏输入、原版截断规则、跨午夜/重叠项目统计，以及实际 HTTP 资源与非资源请求。

数据测试执行原版函数，仅替换 FileReader、下载、localStorage 与界面刷新边界；不等同真实浏览器端到端检查。打包字节一致是本次恢复基线检查：未来批准的业务改动会使该测试失败，应在批准新版基线时有意识更新策略，不应随意删除断言。浏览器计时、权限、打印及 Office 实际布局仍需独立验证。

## 原有数据迁移：每个用户分别备份

浏览器存储不会因为保留键名就自动迁移。原 file 地址、移动后的文件、不同浏览器、localhost/127.0.0.1、不同端口可能对应不同数据空间。项目文件本身不包含你的个人记录。

1. 在原来使用的浏览器和原 HTML 入口打开工作台。
2. 对每个需要保留的用户，分别选择该用户并执行“导出当前用户备份”。备份文件保管到其他位置。先结束正在进行的计时并保存工作。
3. 打开恢复版入口，执行“导入备份到独立用户”。每次导入创建一个独立用户；同名自动区分，不覆盖原有用户。
4. 核对每个用户的记录数、日期、成果、任务、完成状态与各周期统计，核对通过前保留旧入口及所有备份。

JSON 导出格式为 version 3，包含当前用户名称、records 与 tasks，不是所有用户的总备份，也不包含未提交草稿、正在进行的计时或临时编辑报告。旧的纯记录数组可导入；导入会按原版规则规范化分类、ID、数值和文本，不能承诺任意外部 JSON 无损导入。

## 原版已有风险与恢复边界

以下来自 Reviewer 的静态评估 R1–R8；本轮保留行为，未声称全部在浏览器复现或已经修复：

- localStorage 启动不可用时进入临时内存模式，关页丢数据；启动后配额不足、读取损坏或多键写入失败没有完整事务/恢复机制。
- 心流、会议或任务计时期间切换/新建/导入用户可能影响计时归属；使用时先结束计时再切换。
- 心流正常离页只是尽力保存，依赖项目名、有效时长及浏览器事件；强制结束不保证保存。会议/任务计时和草稿无崩溃恢复。BFCache 事件顺序需实际浏览器检查。
- 导入未严格校验 app/version 和日期时间有效性，发生存储写入失败时没有完整回滚。记录标题/项目/长文本与任务有原版长度限制（200/120/5000/240 字符等）。
- 同起止时间按 24 小时处理；计时使用墙上时间且有最小一分钟/24 小时边界。跨日及系统时钟变化需注意。
- 多标签无并发冲突保护；本地用户只是数据分组，无账号认证或云端同步。
- PPT 按 12 个非空行分片，长单行可能超出固定正文框。Word/PPT 可编辑性与实际软件显示需 Reviewer 检查。
- PDF 按钮打开打印窗口，需允许弹窗并在浏览器选择“另存为 PDF”；复制功能受浏览器权限影响。

恢复引入的运行差异：开发入口需 HTTP 服务，且使用自己的浏览器存储空间；打包分发入口继续为原版单 HTML。本轮自动检查未发现打包内容或所测数据行为回归，这不替代完整浏览器和 Office 验收。详见 `docs/recovery/reviewer-assessment.md`。

## Git 版本备份与历史恢复

GitHub 版本备份应包含 `src/`、`scripts/`、`tests/`、`reference/`、项目说明与 `dist/` 下的可交付 HTML/ZIP；临时打包目录、浏览器测试截图/备份、凭据及个人数据不应上传。`.gitignore` 已排除这些常见本地产物，但不是敏感信息扫描器：提交前仍须检查 `git status --short`、`git diff --cached --stat` 和 `git diff --cached`；不要用 `git add -f` 绕过忽略规则上传个人文件。仓库地址和权限由项目负责人确认，只有实际推送成功的提交才是远程备份。

本机损坏后，在安装 Git 和 Node.js 的新电脑上，使用已确认的仓库地址克隆：`git clone <仓库地址>`。进入克隆目录后运行 `node scripts/serve.mjs`，或用 `node scripts/build.mjs` 重新生成分享文件；无需安装 npm 包。

查看历史版本可用 `git log --oneline`。需要恢复某个旧版本时，先保留当前工作，从该提交创建恢复分支：`git switch -c recovery-<版本名称> <提交ID>`，再运行构建和测试。不要直接硬重置或覆盖未提交改动；当前分支版本仍保留在原分支。已发布的版本也可从对应提交/标签取得当时的分享 ZIP。

**浏览器个人工作记录不随源码/GitHub 备份保存。** 必须按上文为每个用户单独导出 JSON，保存到独立、可靠的私人备份位置。新电脑打开页面后需导入这些 JSON；仅恢复仓库无法找回旧电脑浏览器中的记录。
